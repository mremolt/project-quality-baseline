# Generated API Clients in Angular

The Angular parts of the generated-client rules in [typescript-openapi-clients.md](typescript-openapi-clients.md). The rule IDs are the `TS-API-*` IDs of that doc; this file adds the Angular mechanism. Wiring: [05-building-block-view/angular.md](../../05-building-block-view/angular.md).

## Rules

- **TS-API-03 in Angular: `client: 'angular'`.** Orval generates `HttpClient` services, so the interceptors from `src/platform/adapter/out/http` (auth, XSRF, error reporting, NG-ARCH-12) apply to every call. The `angular-query` client is not used.
- **TS-API-04 in Angular: `override.angular.provideIn: false`.** The generated services are not `providedIn: 'root'`; the feature's `<feature>.providers.ts` lists them, and only the adapter injects them (NG-ARCH-10).
- **TS-API-06 in Angular: the adapter converts the generated service's `Observable` with the shared `untilAborted` helper** in `src/platform/adapter/out/http`, never with a bare `firstValueFrom` (which ignores the signal) or `toPromise`.
- **TS-API-07 in Angular:** batching and caching decorators are bound to the port token in the providers file (`useFactory` wrapping the plain adapter).

## Configuration

```ts
// orval.config.ts (Angular client block; the rest as in typescript-openapi-clients.md)
output: {
  // …
  client: 'angular',                           // HttpClient services: interceptors (auth, XSRF) apply
  override: { angular: { provideIn: false } }, // provided by the feature's providers file, not root
  urlEncodeParameters: true,                   // TS-API-09: path parameters encoded
},
```

## Adapter

```ts
// http-orders.ts
@Service({ autoProvided: false })
export class HttpOrders implements LoadOrdersPort, CancelOrderPort { // bound to both tokens with useExisting (NG-ARCH-10)
  private readonly api = inject(OrdersApiService); // generated by Orval (name follows the spec's tag)

  async loadOrders(customerId: CustomerId, signal?: AbortSignal): Promise<readonly Order[]> {
    const dto = await untilAborted(this.api.listOrders({ customerId: customerId.value }), signal);
    return ListOrdersResponse.parse(dto).items.map(toOrder); // zod schema from generated/*.zod.ts: PascalCase operationId + `Response` (Orval 8.47)
  }

  // cancelOrder(command, signal) follows the same pattern
}

// small helper in src/platform/adapter/out/http: Observable → Promise of the first value (firstValueFrom + takeUntil).
// Unsubscribing removes the abort listener; a source that completes without a value rejects with EmptyError.
export async function untilAborted<T>(source: Observable<T>, signal?: AbortSignal): Promise<T> {
  signal?.throwIfAborted();
  try {
    return await firstValueFrom(signal ? source.pipe(takeUntil(fromEvent(signal, 'abort'))) : source);
  } catch (error) {
    signal?.throwIfAborted(); // aborted: reject with the signal's reason, not with EmptyError
    throw error; // the source failed or completed without a value
  }
}
```

## Skill overrides (`orval` skill)

| Skill says | Our rule |
|---|---|
| `angular-query` / TanStack Query clients for Angular with signals | Not used; plain `angular` client behind ports (TS-API-03) |
| `provideIn: 'root'` for generated services | `provideIn: false`; provided by the feature (TS-API-04) |

## Agent checklist

- [ ] `client: 'angular'` with `provideIn: false` and `urlEncodeParameters: true`; generated services listed in the providers file?
- [ ] Observables converted with `untilAborted`, never `firstValueFrom` alone or `toPromise`?
