# React SPA templates

A complete, minimal React SPA (React 19 with the React Compiler, Vite 8, TanStack Router and Query, Redux Toolkit, MUI 9, React Hook Form, use-intl, Orval, Vitest, Playwright): platform rings, runtime configuration, error reporting, HTTP mutator, strict CSP with Trusted Types, one example feature `orders`, tests and tooling (REACT-ARCH-17). Last checked on 2026-11-21: after copying per the table below, `npm install`, `npm run verify` (format, lint, dependency-cruiser, unit and component tests, build, bundle check) and `npm run build && npm run e2e` (built `dist/` behind the CSP server) were green in Chromium and Firefox, including the viewport, dark, high-contrast and forced-colors projects; WebKit could not be started on the check machine. That covers what the checks assert, not every option: parts whose effect no test asserts carry a "verify before first use" comment (the marked options in `src/shared/ui/theme.ts`, the WebKit and nightly projects and the smoke tier in `playwright.config.ts`) and are listed in the docs. Versions in `package.json` were at least 7 days old when pinned (`min-release-age`, TS-TOOL-11).

Copy everything into `frontend/` (REPO-TOOL-03), then:

1. Rename the app: `name` in `package.json`, `<title>` in `index.html`, `app.name` and `platform.documentTitle` in `src/i18n/*.json`.
2. Point `orval.config.ts` at the backend's spec (`../backend/openapi/<api>.yaml` in a product repo, TS-API-01) and delete `openapi/` there; in a separate frontend repository keep the copied spec in `openapi/`.
3. Rename the example feature `orders` (folder, file names, the use-case object and context in `orders.tokens.ts`, `orders.api.tsx`, slice, keys, catalog namespace, route in `src/app/router.tsx`, the E2E stubs and the `orders.composition-` chunk name in `e2e/orders.spec.ts`) or keep it as the model for the first real feature and delete it afterwards. The fixture tree under `test/fixtures/arch-violation/` stays as it is.
4. Run `npm run verify`, then `npm run build && npm run e2e`. `npm run e2e:nightly` adds the nightly projects; `npm run e2e:smoke` needs `SMOKE_BASE_URL`, the URL of a running BFF with the backend (TS-TEST-10, TS-TEST-18).

There is no `config.json` in the template: it is not part of the build (REACT-CFG-06). Locally the Vite dev server proxies `/config.json` and `/api` to the BFF on port 8080; tests stub it (`e2e/fixtures.ts`, MSW). The BFF's frontend configuration must provide every field of `RuntimeConfigSchema` in `src/platform/adapter/out/http/http-runtime-config.ts`, including `release` (REL-VER-05).

Not in the template, add when the product needs it: the language switch (REACT-I18N-12), `onError`/`getMessageFallback` on the `IntlProvider` (REACT-I18N-08), navigation by window size and `useWindowSize()` (REACT-UI-15/17), the locale Playwright projects (TEST-I18N-02). These are marked "verify before first use" in the docs.
